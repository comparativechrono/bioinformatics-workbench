Text tools

Most bioinformatics files are text. The GNU tools – grep, sed, awk, sort, cut, uniq, wc – answer many questions in one line, without a program of their own.

The examples work in a folder of your own:

Look and count

head -3 /data/examples/tables/yeast_genes.csv | cut -c 1-120
wc -l /data/examples/tables/yeast_genes.csv
grep -c ">" /data/examples/sequences/myoglobins.fasta

Columns: cut, sort, uniq

# essential genes (column 3 of the yeast table: 1 = essential)
cut -d, -f3 /data/examples/tables/yeast_genes.csv | tail -n +2 | sort | uniq -c
# the variant positions of a VCF, as a list
bcftools view -H /data/examples/variants/NA12878.calls.vcf.gz | cut -f 1,2 | head -5

Careful with cut -d, on CSV files: a field with a comma inside quotes is cut there too. In the yeast table the location ("Golgi, vesicles & vacuole") and the description have such commas, so every column after the location – the chromosome is column 16 – would be counted wrong. gawk can read the quoted fields (FPAT describes what a field looks like); pandas and R read CSV files properly too:

# genes per chromosome (column 16), most first
awk -v FPAT='[^,]*|"[^"]*"' 'NR > 1 { print $16 }' /data/examples/tables/yeast_genes.csv | sort | uniq -c | sort -rn | head -5

grep: lines that match

grep -i "kinase" /data/examples/tables/yeast_genes.csv | wc -l
grep -v "^#" /data/examples/annotation/cyp2c_slices.gff3 | cut -f 3 | sort | uniq -c

-i ignore case, -v lines that do not match, -w whole words, -c count, -E extended regular expressions, -o only the matching part, -P Perl patterns.

awk: tables and arithmetic

# mean quality of the variant calls
bcftools view -H /data/examples/variants/NA12878.calls.vcf.gz | awk '{ s += $6; n++ } END { printf "%d calls, mean QUAL %.1f\n", n, s / n }'
# the gene lines of a GFF file: column 3 is "gene" (grep -w gene would find the mRNAs too – their
# column 9 says Parent=gene:…)
awk -F'\t' '$3 == "gene"' /data/examples/annotation/cyp2c_slices.gff3 | cut -f 1,4,5,9 | cut -c 1-100
# GC content of the reads (the sequence is every 4th line, from the 2nd; gsub counts what it replaces)
awk 'NR % 4 == 2 { n += length($0); gc += gsub(/[GC]/, "") } END { printf "%d reads, GC %.1f%%\n", NR / 4, 100 * gc / n }' /data/examples/reads/NA12878_R1.fastq

sed: change text

# shorter sequence names
sed 's/^>MyG_/>/' /data/examples/sequences/myoglobins.fasta | grep ">"
# lines 5 to 8 of a file
sed -n '5,8p' /data/examples/reads/NA12878_R1.fastq

sed -i changes a file in place (on your own copy – the examples are read-only).

JSON and the web: curl, jq

curl -s "https://rest.ensembl.org/lookup/symbol/homo_sapiens/CYP2C19?content-type=application/json" | jq '{id, start, end, strand, biotype}'
curl -s -o P02185.fasta "https://rest.uniprot.org/uniprotkb/P02185.fasta" && head -2 P02185.fasta

curl and wget reach web services that allow web pages to use them (Ensembl, UniProt, NCBI E-utilities, EBI, the PDB, …). Others fail with a message about the server; download such files with your browser and upload them in the Files tab.

Compressed files and archives

gzip -c /data/examples/sequences/pBR322.fasta > pBR322.fasta.gz
zcat pBR322.fasta.gz | head -2
tar -czf examples.tar.gz -C /data/examples sequences
tar -tzf examples.tar.gz
zip -r sequences.zip /data/examples/sequences > /dev/null && unzip -l sequences.zip

gzip, gunzip and zcat are carried out by bgzip; zip, unzip and tar (with z for .tar.gz) work on your files.
