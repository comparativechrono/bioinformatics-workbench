Galaxy

Galaxy runs analysis tools from forms, keeps every result in a history with a record of how it was made, and joins tools into workflows. This one works like usegalaxy.org and its sister servers – and runs in your browser, with the same programs as the terminal.

The three columns

  • Tools (left): Upload Data, and the tools in sections. Search them with the box above the list.
  • The middle: the form of a tool, a dataset, the details of a job, or the workflow editor.
  • History (right): your datasets, newest at the top, numbered. Grey: waiting; yellow: running; green: ready; red: failed. Click a dataset to open it.

Hide the help pane (Ctrl+\) to give Galaxy room.

Get data

Upload Data has three sources:

  • From your files – the files in your home folder and the example data; tick them and press Start. The Files tab sends files here too (⋯ → Upload to Galaxy).
  • From your computer – choose files or drop them.
  • Paste text – a few sequences, a list of positions …

Galaxy decides the datatype from the name and content (fastqsanger for reads, fasta, bam, vcf, bed, tabular …); tools offer only the datasets of the types they read. If it guessed wrong, choose the type in the upload form. Compressed text files (.fastq.gz, .fa.gz) are uncompressed on the way in.

Run a tool

  1. Click a tool. Its form lists its inputs – choose datasets from your history – and its settings, with Galaxy's own help under the form.
  2. Run tool. The new datasets appear at the top of the history; wait for them to turn green.
  3. Open a dataset: shows it (tables as tables, HTML reports, trees drawn), downloads it, copy to my files puts it in ~/galaxy for the terminal and notebooks. BAM, VCF and BED datasets have to show them in the Genome browser.

A first analysis with the example reads: upload NA12878_R1.fastq, NA12878_R2.fastq and reference.fa; run fastp on the two read files; Map with minimap2 with the reference and the two trimmed outputs; bcftools mpileup on the BAM, then bcftools call, then bcftools filter. Each step takes seconds.

The tool IDs and versions are those of the Galaxy Tool Shed, so a workflow made here opens on usegalaxy.org (see Workflows) – except Kalign and MUSCLE: the Tool Shed has no tool for the versions here, so a server shows those steps as missing and you choose its own alignment tool there. Kallisto quant and Salmon quant carry the IDs of the newest tools of the Tool Shed, which run kallisto 0.48.0 and Salmon 1.10.1; here they run the terminal's kallisto 0.52.0 and Salmon 2.8.0, so a server's results can differ a little. Call variants with LoFreq runs lofreq call on one core where a server runs lofreq call-parallel. Kraken2 carries the ID of the Tool Shed's newest Kraken2 tool, which runs Kraken2 2.17.1; here it runs the terminal's 2.17.2. Its database is the example one: a server offers the databases its administrators installed. featureCounts and Salmon quant count on several threads: they need the page to be cross-origin isolated (see Limits).

How was this made? Dataset details

The of a dataset shows Galaxy's record of it: the tool and its version, the versions of the programs (dependencies), the command line that ran, every parameter, and the program's messages. That record is why Galaxy analyses can be repeated – and the first place to look when a dataset is red. opens the tool again with the same inputs and settings.

The history

  • Click the history's name to rename it.
  • × deletes a dataset; the history's ⋯ shows deleted datasets (to undelete them) and purges them, which frees their space.
  • ⋯ → Open the history as a notebook (or download it as .ipynb): every upload and job as a %%bash cell with its command, inputs and parameters. Run the notebook and it makes the same datasets again, as files data1.fastq, data2.bam …
  • ⋯ → Start a new history clears it (your workflows stay).

The history and its datasets are kept in this browser with your files (see where your files are kept).

Different from a Galaxy server

  • The tools are a selection, run with the programs of the terminal, one job at a time.
  • There is one history and no user account; nothing is shared with others.
  • Datasets have no genome build ("database: ?") unless a tool passes one on.
