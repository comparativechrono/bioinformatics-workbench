RStudio

RStudio is the IDE that most people use for R. The one in the IDE tab is an imitation, made for teaching, that works in the same way: you write scripts and reports in an editor, run them in the Console, and see your objects, plots and help pages in the panes around them.

The four panes

PaneWhat it is for
Source (top left)the scripts and documents you are editing, each in a tab of its own, and data frames opened with View()
Console (bottom left)R itself: type a command and press Enter. Next to it, Terminal is a shell with the same programs as the workbench’s Terminal tab, and Background Jobs shows what R prints while it knits a report.
Environment (top right)the objects in R’s memory, and Import Dataset for reading in a data file; the History tab lists the commands you have run
Files, Plots, Packages, Help and Viewer (bottom right)your files, the plots you have drawn, the installed packages, R’s help pages, and web pages such as knitted reports and Shiny apps

You can drag the borders between the panes to change their sizes. The menus at the top have the same commands as in RStudio, and Help ▸ Keyboard Shortcuts Help lists the keys.

Scripts

A script is a text file of R commands, saved with the extension .R. To start one, choose File ▸ New File ▸ R Script, or click New script in RStudio under this example, which reads the workbench’s table of yeast genes and draws a plot:

genes <- read.csv("/data/examples/tables/yeast_genes.csv")
str(genes)

# how many genes in each part of the cell are essential (1) or not (0)?
table(genes$location, genes$essential)

boxplot(protein_length ~ essential, data = genes, log = "y",
        names = c("not essential", "essential"),
        ylab = "Protein length (amino acids)")

Put the cursor on the first line and press Ctrl+Enter (⌘+Enter on a Mac). The line is run in the Console, and the cursor moves on to the next line, so you can keep pressing the same keys to work through the script. A command that spans several lines, such as the boxplot() above, is run as a whole, and if you select some lines first, just those lines are run. Source (Ctrl+Shift+S) runs the whole script.

Save your script with Ctrl+S; the first time, RStudio asks for a name. Because the script holds every step of your analysis, you can clear R’s memory at any time with Session ▸ Restart R, and get all your objects and plots back by running the script again.

Packages

RStudio works like R on your own computer: a package has to be installed once, with install.packages(), before library() can load it. (The notebooks are different: they install a package by themselves the first time that library() asks for it.) The packages come ready-built for webR, the version of R that runs in a browser. Most CRAN packages are there, including ggplot2 and dplyr, and so are many Bioconductor packages, such as DESeq2, edgeR and Biostrings.

install.packages("ggplot2")
library(ggplot2)

genes <- read.csv("/data/examples/tables/yeast_genes.csv")
ggplot(genes, aes(gc_content, codon_bias)) +
  geom_point(alpha = 0.3) +
  labs(x = "GC content (%)", y = "Codon bias")

Installing a package takes a little while, because the package and the other packages it needs have to be downloaded. You only have to do it once: the workbench remembers what you have installed, and fetches it again whenever library() needs it, on later visits too. The Packages pane lists what is installed, and Tools ▸ Install Packages… does the same as install.packages().

Looking at your data

The Environment pane lists your objects. Click the arrow next to a data frame to see its columns, or click the table icon at the end of its row (or type View(genes)) to open it as a table in the Source pane, where you can sort and filter it. Import Dataset, at the top of the pane, reads a CSV or Excel file through a dialog, and shows you the code that it runs, which you can copy into your script. Plots appear in the Plots pane, where the arrows take you back to earlier plots and Export saves one as a picture. To read R’s documentation, type ?mean or help(mean), or search in the Help pane.

Reports: R Markdown and Quarto

An R Markdown document (.Rmd) contains your text, written in Markdown, and your R code in chunks. You can run a single chunk with the green ▶ at its top right, and its output appears underneath it. Knit (Ctrl+Shift+K) runs the whole document from the beginning, in a new R session, and turns it into a web page with your text, code and results. The page opens in the Viewer and is saved next to the document as an .html file. Quarto documents (.qmd) are written in much the same way, and have a Render button instead of Knit.

---
title: "Essential genes in yeast"
output: html_document
---

Are the proteins of essential genes longer than the others?

```{r}
genes <- read.csv("/data/examples/tables/yeast_genes.csv")
tapply(genes$protein_length, genes$essential, median)
```

The median lengths are given for non-essential (0) and essential (1) genes.

Because knitting starts with an empty R session, the document has to create or read in everything it uses. An object that you made in the Console, but not in the document, won’t be there, and knitting stops with an error such as object 'genes' not found. That is what makes a knitted report trustworthy: it shows that the code, exactly as written, produces the results. An R Notebook (File ▸ New File ▸ R Notebook) is different. Its Preview saves a web page of the document as it is on screen, with the outputs of the chunks you have run, without running anything again.

Shiny apps

A Shiny app is an interactive web page written in R, in which sliders, menus and buttons change what R calculates and draws. File ▸ New File ▸ Shiny Web App… creates a small example app in a folder of its own, and Run App starts it in the Viewer pane. The first time, RStudio offers to install the shiny package, which takes a minute or two. While an app is running, the Console is busy, just as it would be on your computer, so press Stop (or Esc) when you have finished with it.

Shiny apps rely on the page’s service worker, a small helper that the browser runs for the workbench. If your browser doesn’t allow service workers, as some private windows don’t, RStudio tells you that the app can’t be shown.

Where R looks for files

RStudio’s R starts in your home folder, ~, so read.csv("data/counts.csv") reads the file ~/data/counts.csv. getwd() shows which folder R is in, and Session ▸ Set Working Directory changes it, for example to the folder of the script you are editing. When you knit a document, its code runs in the document’s own folder. The example data are in /data/examples, and you can read them from anywhere by giving their full paths.
