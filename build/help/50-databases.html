Databases

The Databases tab asks public bioinformatics databases your questions, straight from the browser: proteins and structures, genes and genomes, variants, interactions, pathways, papers and small molecules. Every answer can be kept – saved among your files, or sent to a notebook as Python or R code that asks the same question again.

Ask a question

  1. Click a card. Cards that answer several kinds of question have tabs at the top – Ensembl has Gene, Sequence, Variant effect (VEP), Orthologues and Genes in a region.
  2. Fill in the form, or click one of the examples after Try: – they fill in the form and search.
  3. Search. The answer appears under the form: a title and a short summary, then a table (click a column heading to sort by it), a picture or a sequence.

← All databases goes back to the cards. Help opens the card's page in this pane; About the API opens the service's own documentation.

Keep the answer

The buttons above an answer:

  • Save to my files (a sequence, a report) and Save the table (.tsv) – it asks where, in ~/data unless you change it; structures go to ~/structures. From there the terminal, the notebooks and Galaxy can use them.
  • Send to notebook → Python (requests) or R: adds a cell with code that makes the same query to the notebook that is open. Run it, and the answer is in Python (a dictionary, or a pandas table) or in R – ready for the next step of an analysis.
  • Raw data (JSON): what the service sent back, unchanged – every field, also those the table leaves out.
  • Copy the URL: the query as a web address. Paste it into a browser, into curl, or into code.
  • Some answers have more: Show in the 3D viewer (AlphaFold, PubChem), Show in the Genome browser (Ensembl genes), Open in Networks (STRING, IntAct, NDEx), a FASTA file for each transcript (Ensembl), Open at … the service's own page.

Your queries – as a notebook

Under the cards, Your queries lists the questions you asked in this visit, newest first – those of the UniProt and PDB cards too. Save as a Python notebook (or … as an R notebook) writes them all into one notebook, ~/notebooks/database-queries-DATE.ipynb: for each query a heading, its URL and a code cell that makes it again. It is a record of where your data came from; download it from the Notebook tab like any other notebook.

Asking from code

Each card uses a REST API: a web address goes in, data comes out – JSON for most, FASTA or text for sequences. The same works in a notebook:

import requests

r = requests.get("https://rest.ensembl.org/lookup/symbol/homo_sapiens/CYP2C19",
                 headers={"Content-Type": "application/json"})
r.raise_for_status()          # stop here if the service said no
gene = r.json()
gene["id"], gene["seq_region_name"], gene["start"], gene["end"]
library(jsonlite)
gene <- fromJSON("https://rest.ensembl.org/lookup/symbol/homo_sapiens/CYP2C19?content-type=application/json")
c(gene$id, gene$seq_region_name, gene$start, gene$end)

In the browser, R can only make GET requests (a URL); for services that need a POST request – BLAST, VEP with positions, the PDB search – use Python. More in the recipe Databases from code.

Good practice

  • Databases change. New releases add, correct and remove entries; a query can give another answer next month. Note the date – the notebook of your queries does – and, for positions on a genome, the assembly: GRCh38 (hg38) and GRCh37 (hg19) number the same base differently.
  • Annotations are predictions. VEP calls rs4244285 synonymous – yet it is CYP2C19*2, a loss-of-function allele that changes the splicing of the gene (see Genes, genomes and variants). Look at the clinical significance and the literature before you conclude.
  • The services are shared by scientists everywhere. Ask for what you need, not thousands of queries in a quick loop: Ensembl allows about 15 requests a second, NCBI 3. A request that gets no answer at all is sent again (twice) by the tab; for code, see the recipe.
  • When a query fails, the message says why: Not found (404) – check the identifier; did not accept the query (400) – check what you typed; slow down (429) – wait a minute; not answering (5xx) or no answer that the page could read – the service is busy or down: try again later.
Public services

Only what you type into a form is sent to the service (for BLAST, also your e-mail address). These are public services that keep logs: never type or paste personal or patient data into them.
