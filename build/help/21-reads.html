Reads: quality, trimming, simulation

FASTQ files hold reads with a quality for every base. fastp checks and trims them, cutadapt finds and removes adapters and primers, seqtk does many small jobs, wgsim makes simulated reads from a reference.

The examples work in a folder of your own:

A look at the reads

head -8 /data/examples/reads/NA12878_R1.fastq
seqtk fqchk /data/examples/reads/NA12878_R1.fastq | head -4

Each read is four lines: @name, the bases, +, and one quality letter per base (Phred+33: I = 40, 5 = 20, + = 10). seqtk fqchk summarises the bases and their qualities.

fastp: quality control and trimming

fastp -i /data/examples/reads/NA12878_R1.fastq -I /data/examples/reads/NA12878_R2.fastq \
      -o trimmed_R1.fastq -O trimmed_R2.fastq \
      --detect_adapter_for_pe --cut_tail -q 20 -l 50 \
      -h fastp.html -j fastp.json
open fastp.html

With these options fastp removes adapters, trims low-quality bases from the 3′ ends (--cut_tail), and drops reads with too many bad bases or fewer than 50 bases left; the two output files stay in step (read for read). Without --cut_tail or --cut_front fastp trims no ends: it removes adapters and drops poor reads. The HTML report shows quality, GC content and duplication before and after; fastp.json has the same numbers for a script (jq .summary fastp.json).

OptionMeans
-q 20a base is good with Phred quality ≥ 20
-u 40drop a read with more than 40 % bad bases (the default)
-l 50drop reads shorter than 50 bases after trimming
--cut_tailtrim low-quality bases from the 3′ end in a sliding window
--detect_adapter_for_pefind the adapters of paired-end reads from the reads themselves

cutadapt: adapters, primers and quality

When a DNA fragment is shorter than the read, the sequencer reads on into the adapter at the end of the fragment. /data/examples/trimming/ has 384 read pairs of a yeast RNA-seq run that were chosen because many of them do: Cutadapt looks for the adapter you give it in every read and cuts it off, with everything after it.

cutadapt -a AGATCGGAAGAGCACACGTCTGAACTCCAGTCA -A AGATCGGAAGAGCGTCGTGTAGGGAAAGAGTGT \
         -o trimmed_1.fastq -p trimmed_2.fastq \
         /data/examples/trimming/SRR6357070_adapters_1.fastq /data/examples/trimming/SRR6357070_adapters_2.fastq > cutadapt_report.txt
head -20 cutadapt_report.txt

The report says that 205 of the 384 first reads, and 209 of the second, had the adapter, and how many bases went. Further down, the table Overview of removed sequences counts the matches by length and compares them with the number expected by chance (expect): many matches of 3 or 4 bases are chance – -O raises the shortest overlap that counts.

OptionMeans
-a SEQ / -A SEQa 3′ adapter of read 1 / read 2: the adapter and what follows it are removed
-g SEQ / -g ^SEQa 5′ adapter or primer (with ^: only at the very start of the read)
-q 20trim bases below quality 20 from the 3′ end (before the adapter is searched)
-m 30discard reads (pairs) shorter than 30 bases after trimming
-e 0.1, -O 3errors allowed in a match (a fraction of its length); the shortest match that counts
--poly-a, --trim-ntrim poly-A tails; trim N bases from the ends
--discard-untrimmedkeep only the reads in which the adapter was found (amplicons, primers)
--json report.jsonthe report as JSON too (for MultiQC, or jq)

The adapter sequence comes from the library kit; AGATCGGAAGAGC, the start of Illumina's TruSeq adapters, finds most of them. Cutadapt reads and writes .gz files, and prints the reads to the standard output when there is no -o (cutadapt -a … reads.fastq | head). Here it runs on one core (-j is left out) and, being a Python program, takes a few seconds to start. Galaxy has it as Cutadapt.

seqtk: small jobs

# FASTQ to FASTA
seqtk seq -a /data/examples/reads/NA12878_R1.fastq > R1.fasta
# 500 random pairs: the same seed (-s) for both files keeps the pairs together
seqtk sample -s 7 /data/examples/reads/NA12878_R1.fastq 500 > sub_R1.fastq
seqtk sample -s 7 /data/examples/reads/NA12878_R2.fastq 500 > sub_R2.fastq
# length and base counts of each sequence
seqtk comp /data/examples/sequences/myoglobins.fasta | cut -f 1,2

Also: seqtk trimfq (trim by quality), seqtk subseq (pick sequences by name), seqtk rename. seqtk alone lists its commands.

wgsim: simulated reads

Simulated reads from a known sequence are a good way to test a pipeline: you know where every read belongs.

wgsim -N 2000 -1 100 -2 100 -e 0.01 -r 0.001 -S 11 /data/examples/reads/reference.fa sim_R1.fastq sim_R2.fastq
head -4 sim_R1.fastq

-N pairs, -1/-2 read lengths, -e error rate, -r mutation rate, -d/-s fragment length and spread, -S seed. A read's name says where it came from (human_CYP2C19_12642_13173_…). This build does not print the list of mutations it made.
