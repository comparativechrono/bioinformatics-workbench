Spyder

Spyder is an IDE for Python that was designed with scientists in mind. The one in the IDE tab is an imitation, made for teaching, that looks and works like Spyder 6: you write scripts in the Editor, run them in the IPython Console, and look at your variables, plots and documentation in the panes beside them.

The panes

PaneWhat it is for
Editor (left)your scripts, each in a tab of its own, with syntax colouring, completion and warnings about likely mistakes
IPython Console (bottom right)Python itself: type a command and press Enter. This is the real IPython, so its own commands, such as %timeit and %pip, work too. The History tab next to it lists the commands you have run.
Variable Explorer (top right)the variables in the console’s memory, with their type, size and value; double-click one to look inside it. The tabs next to it are Help (documentation), Plots (your figures), Files and the Debugger.

The View menu brings any pane to the front, and View ▸ Reset window layout puts the panes back where they started. Spyder opens in its dark theme; you can switch to a light one in Tools ▸ Preferences, which also has settings for the Editor, for running files and for the console.

Running code

Try this script: New file in Spyder, under it, opens it in the Editor.

import pandas as pd
import matplotlib.pyplot as plt

# %% Read the table of yeast genes
genes = pd.read_csv("/data/examples/tables/yeast_genes.csv")
print(genes.shape)

# %% The fraction of essential genes in each part of the cell
by_place = genes.groupby("location")["essential"].mean().sort_values()
print(by_place)

# %% Plot it
by_place.plot.barh(figsize=(6, 4))
plt.xlabel("fraction of genes that are essential")
plt.tight_layout()
plt.show()

There are three ways of running a script, and you will soon find yourself using all of them:

F5Run file saves the file and runs all of it, in the file’s own folder. Spyder types %runfile into the console, followed by the file’s name, so you can see what it is doing.
Ctrl+EnterRun cell runs the cell that the cursor is in. A cell is a part of a script that begins with a line starting with # %%, and the Editor shades the one you are in. Shift+Enter runs the cell and moves on to the next one.
F9Run selection runs the lines you have selected, or the line that the cursor is on, as if you had typed them into the console.

Whichever you choose, the code runs in the console’s Python, so the variables it creates are still there afterwards. You can look at them in the Variable Explorer, or carry on working with them in the console.

The IPython Console

The console is where your code runs. Type a command and press Enter. If the command isn’t finished yet, such as the first line of a for loop, you get a continuation prompt so that you can type the rest. ↑ and ↓ bring back earlier commands, and Tab completes names. A few of IPython’s own commands are worth knowing: name? shows the documentation of an object, %timeit times a line of code, %pip install NAME installs a package, and a line that begins with ! runs a command in the workbench’s terminal, as in !ls -l.

import numpy as np
x = np.random.default_rng(1).normal(size=10_000)
print(x.mean(), x.std())
%timeit np.sort(x)

NumPy, pandas and matplotlib are loaded while Spyder starts. The many other packages that come with Pyodide, such as SciPy, scikit-learn, statsmodels and Biopython (import Bio), are loaded the first time a script or a command imports them. Pure-Python packages from PyPI can be installed with %pip install NAME; they last until you reload the page.

Consoles ▸ Restart kernel (Ctrl+.) starts Python afresh, and Remove all variables clears the variables without restarting. Ctrl+C in the console stops the code that is running.

The Variable Explorer

The Variable Explorer lists the variables in the console’s Python, with their type, their size and a summary of their value, and colours the rows by type. Double-click a variable to open it: a data frame or an array as a table that you can sort and scroll through, a list or a dictionary with its contents, and a number or a piece of text in a box where you can change it. The right-click menu has more, such as plotting an array or drawing it as a histogram. Modules, functions and names that begin with an underscore are hidden; the filter button at the top of the pane changes what is shown.

Plots, help and completion

Figures that your code draws with matplotlib appear in the Plots pane, and in the console as well unless you turn that off in the pane’s menu. The arrows take you back to earlier figures, and the buttons at the top save a figure as a PNG file, copy it, zoom in or remove it.

To read the documentation of a function, put the cursor on its name, in the Editor or the console, and press Ctrl+I: the Help pane shows it. You can also type a name into the Object box at the top of that pane. As you type, Tab or Ctrl+Space offers to complete a name, and Ctrl+G (or Ctrl and a click) takes you to where a function was defined.

The Editor also checks your code as you write it, with pyflakes. A red dot in the margin marks an error, such as a bracket that is never closed, and a yellow triangle marks a warning, such as a name that is used but never defined, or a module that is imported but never used. Hover over the mark to read the message.

The debugger

When a script doesn’t do what you expect, the debugger lets you run it one line at a time and watch your variables as they change. Click just to the left of a line number, or press F12, to put a breakpoint on that line: a red dot appears. Then choose Debug file (Ctrl+F5). The script runs until it reaches the breakpoint, and stops there with the line it is about to run marked in the Editor. The Variable Explorer now shows the variables at that point, and the console’s prompt changes to IPdb [1]:, where you can type Python to look at anything you like.

Ctrl+F10Step: run the current line, and stop at the next one
Ctrl+F11Step into: go inside the function that the current line calls
Ctrl+Shift+F11Step return: carry on until the current function returns
Ctrl+F12Continue: run on to the next breakpoint
Ctrl+Shift+F12Stop debugging

The same commands are on the toolbar, in blue, and in the Debug menu, and the Debugger pane shows how you got to the current line: which function called which. If a script has already stopped with an error, typing %debug in the console takes you to the line where it failed, with the variables as they were at that moment. To have that happen by itself whenever a script fails, tick Directly enter debugging when errors appear in Tools ▸ Preferences.

When the debugger is not available

The debugger, input() and stopping code with Ctrl+C all need Python to pause and wait for you while it is in the middle of running something. A web page can only do that when it is cross-origin isolated. The workbench arranges this itself in most browsers, but not in every situation (in some private windows, for example). If the page is not isolated, the console says so when it starts. Everything else still works, but input() stops with an error instead of waiting for an answer, the debugger can’t be started, and the only way to stop code that runs for too long is Restart kernel. Reloading the page, or opening it in an ordinary window, usually helps; What is different in the browser explains more.

Files and the working directory

The console starts in your home folder, ~. The working directory is shown at the right-hand end of the toolbar, where you can also change it, and the Files pane shows what is in it. When you run a whole file with F5, the working directory changes to the file’s folder, so a script can read the files next to it by their names alone; Run ▸ Configuration per file changes that. In the Files pane, right-click a CSV file and choose Import data to read it into a pandas data frame.

What is different from Spyder on a computer

  • The console’s Python runs inside your browser (Pyodide), and is separate from the Python of the notebooks.
  • Python can’t start threads or other processes, so threading, multiprocessing and subprocess don’t work; use !command for the programs of the terminal.
  • Figures are drawn in the Plots pane and the console only: there are no separate interactive windows, and desktop toolkits such as tkinter and Qt are not available.
  • There are no projects, no plug-ins and no version control.
