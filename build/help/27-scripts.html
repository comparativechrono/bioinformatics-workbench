Scripts and pipelines

Commands that work once belong in a script – so that they run again tomorrow, on new data, and show exactly what was done.

The examples work in a folder of your own:

A bash script

Write the commands into a file – in the Files tab, or with a here-document as below – and run it with bash:

cat > count_reads.sh << 'EOF'
#!/usr/bin/env bash
set -euo pipefail          # stop at the first error
for f in "$@"; do
  n=$(( $(wc -l < "$f") / 4 ))
  echo -e "$(basename "$f")\t$n"
done
EOF
bash count_reads.sh /data/examples/reads/*.fastq

"$@" are the file names given to the script; set -euo pipefail makes it stop at the first command that fails, instead of carrying on with half a result. After chmod +x count_reads.sh it also starts as ./count_reads.sh.

A whole analysis in one script

cat > call_variants.sh << 'EOF'
#!/usr/bin/env bash
set -euo pipefail
ref=/data/examples/reads/reference.fa
r1=/data/examples/reads/NA12878_R1.fastq
r2=/data/examples/reads/NA12878_R2.fastq
fastp -i "$r1" -I "$r2" -o trimmed_1.fastq -O trimmed_2.fastq -h fastp.html -j fastp.json 2> fastp.log
minimap2 -ax sr -R '@RG\tID:NA12878\tSM:NA12878' "$ref" trimmed_1.fastq trimmed_2.fastq 2> minimap2.log | samtools sort -o mapped.bam -
samtools index mapped.bam
bcftools mpileup -f "$ref" mapped.bam 2> /dev/null | bcftools call -mv -Oz -o calls.vcf.gz
bcftools filter -i 'QUAL>=20 && INFO/DP>=5' -Oz -o filtered.vcf.gz calls.vcf.gz
echo "variants: $(bcftools view -H filtered.vcf.gz | wc -l)"
EOF
bash call_variants.sh

Python and R scripts

cat > gc.py << 'EOF'
import sys
from Bio import SeqIO
from Bio.SeqUtils import gc_fraction
for rec in SeqIO.parse(sys.argv[1], "fasta"):
    print(rec.id, f"{gc_fraction(rec.seq):.3f}", sep="\t")
EOF
python gc.py /data/examples/reads/reference.fa
Rscript -e 'x <- read.csv("/data/examples/tables/yeast_genes.csv"); print(table(x$essential))'

Both use the same Python and R as the notebooks. A script's plots go to files: plt.savefig("plot.png") in Python; in R, png("plot.png") … dev.off() (otherwise Rplots.pdf).

Snakemake

Snakemake runs a pipeline from rules: each rule says which files it makes from which, and Snakemake runs only what is missing or out of date. The terminal has a browser edition of Snakemake 9 – snakemake -n shows the plan, snakemake --cores 1 runs it, snakemake --dag | dot -Tsvg -o dag.svg draws it:

mkdir -p ~/smk && cd ~/smk
cat > Snakefile << 'EOF'
rule all:
    input: "results/flagstat.txt"

rule map:
    input:
        ref="/data/examples/reads/reference.fa",
        r1="/data/examples/reads/NA12878_R1.fastq",
        r2="/data/examples/reads/NA12878_R2.fastq"
    output: "results/mapped.bam"
    shell: "minimap2 -ax sr {input.ref} {input.r1} {input.r2} | samtools sort -o {output} -"

rule flagstat:
    input: "results/mapped.bam"
    output: "results/flagstat.txt"
    shell: "samtools flagstat {input} > {output}"
EOF
snakemake -n
snakemake --cores 1
cat results/flagstat.txt

Run snakemake --cores 1 again: nothing to do, because every result is newer than its inputs. Snakemake keeps a record of how each file was made: snakemake --summary.

Graphviz

dot draws graphs written in the DOT language – workflows, networks, decision trees:

echo 'digraph { rankdir=LR; reads -> fastp -> minimap2 -> bcftools -> variants }' | dot -Tsvg -o steps.svg
open steps.svg
