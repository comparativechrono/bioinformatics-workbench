The terminal

A Linux shell (bash) with real bioinformatics programs – samtools, bcftools, minimap2, Bowtie 2, fastp, bedtools and more, compiled to WebAssembly so that they run in your browser.

Where you are

The prompt student@workbench:~$ shows the folder you are in; ~ is your home folder, /home/student. Your files are there (the Files tab shows the same ones); the example data is in /data/examples, read-only – copy what you want to change.

pwd
mkdir -p ~/practice && cd ~/practice
cp /data/examples/sequences/myoglobins.fasta .
ls -l

Getting help

  • help lists every program, with its version.
  • man NAME shows examples for a program (man bcftools); NAME --help lists its options – for a command of samtools or bcftools, samtools sort --help, bcftools view --help (some first say that they do not know the option help, then list the ones they do).
  • A command that fails has a button under it, Ask the AI assistant about this error.

Home / Endto the start / end of the line

A command that needs more than one line (a for loop, a here-document) can be typed line by line: the prompt changes to > until it is complete. Pasting several lines runs them one after the other.

The shell

It is bash: pipes |, && and ||, redirection (> >> < 2> 2>&1), quotes, variables, globs (*.fastq), $( ), $(( )), for/while/if/case, functions, here-documents, <( ) and xargs. Scripts run with bash script.sh. See Scripts and pipelines.

for f in /data/examples/reads/*.fastq; do
  echo "$(basename "$f"): $(( $(wc -l < "$f") / 4 )) reads"
done

Commands of the workbench

open FILE
shows a file in its tab: a notebook in Notebook, a structure in the 3D viewer, the rest in Files (tables, pictures, HTML reports, trees).
nano FILE
edits a file in the Files tab.
igv FILE…
shows BAM, VCF, BED or GFF files in the Genome browser.
download FILE|FOLDER
saves a copy on your computer (a folder as a .zip).
export-session FILE.ipynb
writes the commands of this session, with their output, as a notebook (or FILE.sh: a script).

Saving a session

Save session (above the terminal) keeps the commands you ran, with what they printed: Open as a notebook here (every command in a %%bash cell, in the folder where it ran), Download as a Jupyter notebook, or Download as a shell script. That is a record of your analysis that runs again – in the workbench, or in Jupyter on a computer with the same programs.

Good to know

  • Each program runs on one processor core: options for threads (-@, -t, --threads) are left out, with a note.
  • There are no background jobs (&), no sudo or apt: nothing can be installed in the terminal except Python packages (pip install).
  • Programs have a few gigabytes of memory at most: whole human genomes are too big; regions, exomes of a few genes and bacterial genomes work well.
  • curl and wget reach web services that allow web pages to use them (EBI, UniProt, Ensembl, NCBI…), not every site. See What is different in the browser.
