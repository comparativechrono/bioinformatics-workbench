Keep and share your work

Everything you run in the workbench can become a notebook – a record that shows what you did and runs again. Your files live in this browser: download what you want to keep.

Everything as a notebook

Where you workedHow it becomes a notebook

Download

  • One notebook: Download in the Notebook tab.
  • One file or folder: its ⋯ in the Files tab, or download FILE in the terminal (a folder becomes a .zip).
  • Everything: My files → Download all my files (.zip). Do this at the end of each session if you work on a shared computer – see where your files are kept.

Before you share or hand in a notebook

  1. Restart the language and Run all: the notebook must run from top to bottom without the cells you deleted on the way.
  2. Put a text cell at the top: what the notebook does, with which data, when.
  3. Keep the data with it: copy the input files into a folder of your own, next to the notebook, and download the folder.
  4. Record the versions (below) and the dates of database queries.
  5. Never leave a key, a password or personal data in a notebook – also not in its outputs.

The versions

Results depend on the versions of the programs and packages. A last cell that prints them makes a notebook complete:

import sys, numpy, pandas, matplotlib
print("Python", sys.version.split()[0], "· numpy", numpy.__version__, "· pandas", pandas.__version__, "· matplotlib", matplotlib.__version__)
%%bash
samtools --version | head -n 1
bcftools --version | head -n 1
echo "minimap2 $(minimap2 --version)"
sessionInfo()

Running a notebook elsewhere

A downloaded notebook opens in Jupyter, JupyterLab, VS Code and Google Colab (R notebooks need the R kernel, IRkernel). What the other computer needs:

  • The data, at the paths the notebook uses. /data/examples exists only here: download it (Files tab: the ⋯ of Examples (read-only) → Download as a .zip) and change the paths.
  • The packages: pip install pandas matplotlib biopython requests scipy; in R, install.packages(c("ggplot2", "jsonlite")), and from Bioconductor BiocManager::install(c("DESeq2", "edgeR")).
  • The programs of %%bash cells – with conda, from Bioconda, in the versions used here (or the nearest ones Bioconda has):
conda create -n workbench -c conda-forge -c bioconda \
    samtools=1.17 minimap2=2.22 bowtie2=2.4.2 fastp=0.20.1 \
    seqtk=1.4 bedtools=2.31.0 kalign3=3.3.2 muscle=3.8.1551 fasttree=2.1.11
conda create -n workbench-bcftools -c conda-forge -c bioconda bcftools=1.10
conda create -n workbench-freebayes -c conda-forge -c bioconda freebayes=1.3.6
conda create -n workbench-bwa -c conda-forge -c bioconda bwa=0.7.19 bwa-mem2=2.2.1 hisat2=2.2.2 samtools
conda create -n workbench-rnaseq -c conda-forge -c bioconda subread=2.1.1 kallisto=0.52.0 salmon=2.8.0
conda create -n workbench-stringtie -c conda-forge -c bioconda stringtie=3.0.3
conda create -n workbench-mosdepth -c conda-forge -c bioconda mosdepth=0.3.14
conda create -n workbench-cutadapt -c conda-forge -c bioconda cutadapt=5.2
conda create -n workbench-somatic -c conda-forge -c bioconda lofreq=2.1.5 somatic-sniper=1.0.5.0
conda create -n workbench-strelka -c conda-forge -c bioconda strelka=2.9.10
conda create -n workbench-meta -c conda-forge -c bioconda kraken2=2.17.2 bracken=3.1
conda create -n workbench-annotation -c conda-forge -c bioconda prodigal=2.6.3 hmmer=3.4 bustools=0.45.1
conda activate workbench

bcftools 1.10 needs an older htslib than samtools 1.17, so it has an environment of its own (or take a current bcftools into the first one – its output can differ in details); Bioconda's BWA 0.7.19 needs a newer zlib than samtools 1.17 and FreeBayes 1.3.6, so it goes with a current samtools. featureCounts is in the package subread. StringTie 3.0.3 and mosdepth 0.3.14 each need their own newer HTSlib, and so an environment each. Cutadapt 5.2 needs Python 3.13, where Bowtie 2 2.4.2 needs Python 3.9 or older; LoFreq 2.1.5 needs samtools 1.24 or newer; Strelka 2.9.10 needs Python 2.7 – so each has an environment of its own. Kraken2 and Bracken share one (Kraken2 2.17.2 needs zlib 1.3.2 or newer); a Kraken2 database is not in the package – build one, or download a ready-made one. Prodigal, HMMER and bustools share one too; on a computer HMMER reads .gz files and uses several cores (--cpu). Bioconda has no Kalign 3.3.1; 3.3.2 is the nearest.

Lines that only the workbench understands – igv, open, download – do nothing useful elsewhere: leave them out.
